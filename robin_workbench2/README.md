# 로빈 요리·공구 작업실 2.0

요리 콘텐츠 제작과 공동구매 운영을 한 흐름으로 잇는 로컬 앱입니다.
시청자 불편 수집 → 메뉴 기획 → 조리 테스트 기록 → 콘텐츠 초안 → 공구 FAQ → 성과 기록 → 다음 메뉴 기획.

- 파이썬 기본 기능(tkinter)만 씁니다. 설치할 추가 프로그램, 서버, 유료 서비스가 없습니다.
- 외부 AI·인터넷 연결이 없습니다. 분류·평가는 모두 **규칙 기반 자동 추정**이라고 표시됩니다.
- 게시·댓글 답글·DM·문자 발송·상품 정보 변경 기능이 없습니다. 초안까지만 만듭니다.
- 최종 메뉴, 맛, 조리 안전성, 레시피 완성도, 상품 사용 경험은 로빈님이 판단합니다.

## 처음 실행
1. 파이썬 3.10 이상이 필요합니다. 없으면 python.org에서 설치하고 "Add python.exe to PATH"를 체크합니다.
2. `작업실_열기.cmd`를 더블클릭합니다. 처음에는 **예시 자료** 모드로 열립니다(위쪽 띠가 노란색).
3. 예시로 둘러본 뒤 시작 탭에서 **실제 자료**를 고르면 빈 작업실이 열립니다(띠가 초록색). 다음부터는 마지막 모드로 열립니다.
4. `예시_전체흐름_실행.cmd`는 예시 자료로 전체 흐름을 한 번에 돌려 결과 파일을 만듭니다.

## 화면 순서
| 탭 | 하는 일 |
|---|---|
| 시작 | 지금 단계, 부족한 자료, 예시/실제 전환, 결과·자료 폴더 열기, 백업·복원 |
| 1 자료 입력 | ① 댓글·질문 ② 영상 성과 ④ 상품 정보 ⑤ 공구 문의·결과 입력, CSV 가져오기·내보내기, 빈 양식 받기 |
| 2 불편 분석 | 7가지 분류, 주제별 건수·대표 댓글, 묶음을 고르면 원문·출처·주소, 영상 아이디어(댓글에 없는 욕구는 "추정") |
| 3 메뉴 후보 | 6기준 자동 평가(추정)와 셰프 점수·이유를 따로 저장, 근거 부족은 "보류", 이전 회고 검색, 테마 밥상 추천 |
| 4 조리 기록 | ③ 조리 테스트. "셰프확인=예"인 기록만 초안의 원본이 됩니다 |
| 5 콘텐츠 초안 | 키/풀링 콘텐츠 초안 12개 항목, 항목별 셰프 수정·저장, 다시 만들어도 수정본 유지, 변경 기록, 파일 저장 |
| 6 성과 회고 | ⑦ 회고 입력, 같은 플랫폼·같은 경과시간끼리 지표 비교, 공구 전환율(분모·분자 있을 때만) |

입력 칸 이름 옆 색: 파랑 = 원문, 초록 = 셰프 확인, 갈색 = 자동 추정.

## 자료와 결과 위치
- 자료: `문서\로빈_요리공구작업실2\data\실제` (예시는 `...\data\예시`). 앱 폴더를 새 버전으로 바꿔도 자료는 그대로입니다.
- 결과물(보고서·초안·CSV·양식): `다운로드\로빈_요리공구작업실2_결과\실제` (예시는 `...\예시`)
- 자동 백업: 저장할 때마다 자료 폴더의 `backups`에 이전 상태가 남습니다(최근 50개).
- 수동 백업: 시작 탭 "백업 만들기" → `다운로드\로빈_요리공구작업실2_결과\백업\작업실백업_모드_날짜.zip`
- 복원: 시작 탭 "백업에서 복원" → zip이나 backups의 json을 고르면, 지금 상태를 먼저 백업한 뒤 되돌립니다. 다른 모드의 백업은 거절합니다.

## 실제 자료 넣는 법
- 화면에서 한 건씩: 해당 탭 → "새 항목" → 입력 → "저장".
- 엑셀로 여러 건: "빈 양식 받기"로 받은 CSV에 적고 "CSV 가져오기". 안내 줄과 예시 줄은 지우고 씁니다.
- 가져오기는 전부 검사한 뒤 문제가 없을 때만 넣습니다. 틀린 줄 번호와 고칠 방법을 알려 줍니다. 중복 줄은 건너뛰고 알려 줍니다.
- 양식에 없는 열은 버리지 않고 함께 보관합니다(입력 칸 위 "자동 추정" 상자에 표시).

## 작업실 1.0 자료 옮기기
1.0(2026-09-27, 본부 PC) 원본을 이번 작업 환경에서 읽지 못해, 2.0은 1.0 코드를 보지 않고 새로 만들었습니다.
1.0 자료는 지우지 않습니다. 1.0에서 표별로 CSV를 내보낸 뒤 2.0 실제 모드의 같은 표에서 "CSV 가져오기"를 하면 됩니다.
열 이름이 조금 달라도 흔한 이름(댓글·원문·링크·URL·조회 등)은 자동으로 맞춥니다. 맞지 않는 열은 보관만 합니다.

## 작성 원칙 (초안에 적용)
- 제목과 썸네일을 먼저 정하고 도입부가 그 약속을 잇습니다. 썸네일은 18자 이하, 해결 방법은 넣지 않습니다.
- 시청자 호칭은 기본 "여러분"(화면에서 바꿀 수 있음). 도입부는 공감 → 문제 → 사례 → 볼 이유.
- 재료량·조리 시간·불 세기는 조리 기록에 적힌 그대로만 씁니다. 없으면 "[확인 필요: …]"로 남깁니다.
- 공구 FAQ 답변은 답변 근거가 있을 때만 "근거 있음", 없으면 "확인 필요"입니다. 필요 없는 분과 구매 전 비교 조건도 넣습니다.
- 확인 안 된 판매 문구, 효능·성능 표현, 금지어는 저장 전 점검에서 경고합니다.
- 모든 초안에 원본 조리 테스트 ID, 댓글 ID, 상품 ID, 문의 ID가 붙고, 상태는 "대본 초안 — 완성 영상 아님"입니다.
