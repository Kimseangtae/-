# threads-watch: 스레드 레퍼런스 채널 감시·분석·차용

## 실행 순서 (매 회 동일)

1. **가져오기**
   ```bash
   python3 threads-watch/fetch_threads.py --mark
   ```
   - `new_posts` 가 비어 있으면: 보고서 대신 한 줄 "새 글 없음 (핸들, 확인 시각)" 만 남기고 종료.
   - `fallback` 에 핸들이 있으면: 그 프로필 URL 을 WebFetch 로 직접 읽어 최근 글 텍스트와
     상대 날짜를 뽑는다. WebFetch 는 스레드 SPA 를 렌더링해 글을 돌려준다(검증 완료).
     이 경로로 읽은 글은 `state/seen.json` 에 없으므로 보고서 끝에 URL 을 적어 중복을 막는다.

2. **글별 분석** (새 글 하나마다 아래 6항목, 각 1~2줄)
   | 항목 | 볼 것 |
   |---|---|
   | 유형 | 생활 밀착 / 발견 공유 / 소신발언 / 홍보 / 기타 |
   | 첫 줄 훅 | 상식 뒤집기·숫자·질문·고백·단정 중 무엇인가. 첫 15자를 그대로 인용 |
   | 전개 | 문제→불편→손해→해결 흐름이 있는가. 문장 길이, 줄바꿈 리듬 |
   | 참여 장치 | 질문으로 끝나는가, 선택 강요("A vs B")인가, 경험 소환인가 |
   | 신뢰 장치 | 단점·한계를 먼저 말했는가. 1인칭 실패 사례가 있는가 |
   | 왜 먹혔나 가설 | 한 문장. 확인 불가한 수치는 쓰지 않는다 |

3. **차용 판정** (글마다 셋 중 하나)
   - **차용**: 55~70대 여성, 부엌·식재료·건강·살림 맥락으로 옮길 수 있고 "속지 않는 부엌" 철학과 충돌 없음.
   - **구조만 차용**: 소재는 안 맞지만 훅·전개·마무리 틀은 쓸 수 있음.
   - **패스**: 로빈의밥상 톤과 무관하거나 채널 규칙과 충돌. 이유 1줄.

4. **적용안 작성** (차용·구조만 차용 판정 글마다)
   - 스레드용 글 1편. **스친이들 반말체**. 가르치는 톤 금지. 강한 훅 → 상식 뒤집기 → 참여형 마무리.
   - 원문 구조를 어디서 어떻게 빌렸는지 괄호 없이 한 줄로 설명.
   - 소재는 최근 로빈의밥상 영상·계절 식재료·공구 일정 중에서 고른다. 모르면 계절 식재료로.
   - 필요하면 같은 소재의 유튜브 커뮤니티 글 또는 쇼츠 아이디어 1줄 추가. 쇼츠 CTA 는 "본 영상"으로.

5. **채널 금지 규칙 점검** (출력 전 반드시)
   - "밥깡패" 0건. 오직 "로빈의밥상".
   - 매실액·매실청 없음. 단맛은 알룰로스 또는 채향원 블루베리 와인식초.
   - "체칼" 아님, "채칼".
   - 스레드 글에는 외부 링크·해시태그 남발 금지. 해시태그를 쓰면 #로빈의밥상 포함.
   - 20년 셰프 경력 언급은 글 전체에서 최대 1회.
   - 자리표시자 없이 바로 붙여넣기 가능한 완성본.

6. **보고서 저장·전달**
   - 파일: `threads-watch/reports/YYYY-MM-DD.md` (같은 날 2회째면 `-2` 붙임).
   - 형식: `.claude/skills/threads-watch/report-template.md` 그대로.
   - 저장 후 `git add threads-watch && git commit -m "threads-watch: YYYY-MM-DD 보고서"` 후 현재 브랜치에 push.
   - 대화에는 보고서 전체가 아니라 **차용 판정 요약 표 + 적용안 1순위 글 전문** 만 붙인다.
     나머지는 파일 경로로 안내.

## 판단 기준 메모
- **답글은 자동 수집되지 않는다.** 스레드는 로그인 없이 답글을 내주지 않는다(RSS, WebFetch, 페이지 내장 데이터 모두 확인 완료).
  많은 채널이 "본문 1~3개 + 나머지는 작성자 답글" 구조를 쓰므로, 본문이 번호 목록 도중에 끊기면
  "나머지는 답글에 있음"으로 표기하고 첫 글 기준으로 판정한다. 차용 판정 글은 보고서와 대화 출력에 URL 을
  반드시 넣어 로빈님이 답글까지 직접 확인하게 한다.
- 좋아요·조회수는 RSS 에 없다. 반응 수치를 추정해 쓰지 말고 구조로만 평가한다.
- 홍보성 글(공구·협찬)은 "정보 다큐 위장" 비율을 본다. 교육 90% 에 못 미치면 패스 사유에 적는다.
- 같은 채널에서 반복되는 패턴이 3회 이상 보이면 보고서 맨 위 "패턴 알림" 에 올린다. 이것이 가장 가치 있는 발견이다.
