# 인스타 캐러셀 판독 규칙

이미지 속 글자는 스크립트로 읽지 않는다. **클로드가 슬라이드 이미지를 한 장씩 직접 보고** 옮겨 적는다.
그래서 정확도를 좌우하는 것은 도구가 아니라 아래 규칙을 지키는 방식이다.

## 판독 순서 (캐러셀 1개)
1. `data/ig/<핸들>/posts.json` 에서 그 게시물의 캡션·좋아요·댓글·장수를 확인한다.
2. `slide-01` 부터 **순서대로 한 장씩 Read** 한다. `sheet.jpg` 는 전체 흐름 파악용이지 글자 판독용이 아니다.
3. 장마다 아래를 기록한다. 한 장을 다 적은 뒤 다음 장으로 간다. 몰아서 기억에 의존하지 않는다.
4. 다 끝나면 `python3 gongu-lab/ig_analyze.py validate <핸들>` 로 형식·장수를 검증하고, 오류가 나면 그 장을 다시 보고 고친다.

## 장별 기록
| 필드 | 쓰는 법 |
|---|---|
| `text` | 이미지 속 글자를 **보이는 그대로**. 줄바꿈은 ` / `. 맞춤법을 고치지 않는다. 숫자·가격·단위는 특히 정확히. |
| `visual` | 배경색, 글자색, 제목과 본문의 크기 위계, 사진/일러스트/스크린샷/표 여부, 강조 장치(형광펜·박스·화살표·번호 배지), 여백. 한 줄. |
| `role` | 아래 정의 중 하나 |
| `no_text` | 글자가 정말 없는 장(사진만)일 때만 `true`. 이때 `text` 는 비운다. |

**못 읽는 글자는 추측해서 채우지 않는다.** `[판독불가]` 로 표시하고, 작은 글씨·저대비는 같은 이미지를 한 번 더 본다.
영상 슬라이드(`kind: video`)는 첫 프레임만 보이므로 `visual` 에 "영상 슬라이드, 첫 프레임만 확인" 이라 적는다.

## role 정의
| role | 기준 |
|---|---|
| hook | 첫인상 장. 스크롤을 멈추게 하는 주장·질문·숫자 (보통 1장) |
| problem | 독자의 불편·손해를 말하는 장 |
| cause | 왜 그런지 원인·원리를 설명 |
| evidence | 근거, 수치, 사례, 사진 증거, 후기 |
| steps | 방법·순서·팁 나열 (번호가 붙은 항목들) |
| comparison | 비교(전/후, A/B, 가격 대조) |
| reveal | 정답·반전·결론이 처음 드러나는 장 |
| summary | 앞 내용 요약 |
| cta | 행동 요청(저장, 댓글, 팔로우, 프로필 링크 등) |
| other | 위에 없음 (표지 반복, 로고 등) |

## hook_type 정의 (1장 기준, 하나만)
| 값 | 기준 |
|---|---|
| 상식뒤집기 | "~가 아니라 ~다", "~하지 마세요" 식으로 통념을 정면 부정 |
| 숫자리스트 | "~3가지", "TOP 5" 처럼 개수를 약속 |
| 질문 | 질문형 문장이 중심 |
| 손해경고 | "이거 모르면 손해/버립니다/위험" |
| 비포애프터 | 전후 변화를 보여줌 |
| 권위·경력 | 직업·경력·전문가를 앞세움 |
| 공감·장면 | 생활 장면·감정 공감으로 시작 |
| 기타 | 위에 없음 |

## 나머지 필드
- `cta.type`: 저장 / 댓글 / 팔로우 / 프로필링크 / DM / 공유 / 없음. `cta.slide` 는 그 요청이 나오는 장 번호(없음이면 0), `cta.text` 는 원문. 캡션의 CTA 는 `caption_cta` 에 따로.
- `appeal`: 공구·제품 연결이 있을 때 소구점 3축 중 하나 — **난이도 해소**(어려운 걸 쉽게) / **속도 향상**(빨라짐) / **선택 대행**(고르는 일을 대신). 제품 연결이 없으면 `해당 없음`.
- `gongu`: 캡션·슬라이드·프로필 링크 안내로 보아 공동구매·판매와 연결된 게시물이면 `true`. 확신이 없으면 `false` 로 두고 `notes` 에 근거를 적는다(최종 확정은 로빈님 몫).
- `drawback_first`: 제품·방법의 단점/한계를 장점보다 먼저 말하면 `true`.
- `transferable`: 로빈님 콘텐츠에 **구조로** 가져올 것 1~2줄. 문장·이미지를 그대로 쓰라는 뜻이 아니다. 예: "1장 숫자 약속 → 2~6장 항목 하나씩 → 7장 저장 요청".
- `notes`: 판독 불확실한 곳, 영상 슬라이드, 캡션 특이점.

## analysis.json 형식 (예)
```json
{
  "shortcode": "ABC123",
  "analyzed_on": "2026-10-18",
  "hook_type": "숫자리스트",
  "hook_text": "집게 고를 때 꼭 봐야 할 3가지",
  "appeal": "선택 대행",
  "drawback_first": true,
  "gongu": false,
  "caption_cta": "프로필 링크에서 확인",
  "cta": { "type": "저장", "text": "나중에 쓰게 저장해두세요", "slide": 6 },
  "transferable": "1장 개수 약속 → 2~5장 기준 하나씩 → 6장 저장 요청",
  "notes": "",
  "slides": [
    { "n": 1, "role": "hook", "text": "집게 고를 때 / 꼭 봐야 할 3가지", "visual": "노란 배경, 검정 굵은 제목 중앙, 하단 작은 계정명" },
    { "n": 2, "role": "steps", "text": "1. 무게 / 한 손으로 들어보세요", "visual": "흰 배경, 번호 배지, 사진 우측" }
  ]
}
```
허용 값은 `ig_analyze.py` 상단 `HOOK_TYPES`, `ROLES`, `CTA_TYPES`, `APPEALS` 와 같다. 값이 다르면 `validate` 가 오류로 알려준다.

## 분석 대상 고르기 (중요)
- 반응이 좋은 것만 보면 "다 하는 것"과 "잘 되는 것"을 구분할 수 없다. `rank` 가 만드는 **상위 K개 + 하위 K개** 를 같은 기준으로 판독해 대조한다.
- 캐러셀이 6개 미만인 계정은 순위가 의미 없다. 더 수집하거나 참고용으로만 쓴다.
- 반응 지표는 좋아요·댓글뿐이다. 저장·공유·도달은 외부에서 볼 수 없으므로, 캐러셀에서 가장 중요한 지표(저장)가 빠져 있다는 한계를 보고서에 적는다.
