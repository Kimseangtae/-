# /performance-report — 잘된 것 · 아쉬운 것 · 다음 할 일

## 순서
1. 기간: 인자(예: `2026-11`) 또는 지난 30일.
2. 숫자 모으기
   - `python content-hub/hub.py review --days 30` → 스레드·인스타·페북 자동 수집분 + `done --url` 로 주소 남긴 유튜브
   - 유튜브 채널 전체가 필요하면 `python gongu-lab/yt_research.py channel @로빈의밥상핸들 --save gongu-lab/data/videos/robyn.json` 후 `analyze_videos.py`
   - 로빈님이 붙여넣은 숫자(스튜디오 CTR·시청 지속, 인사이트 저장·공유, 공구 클릭·주문)는 그대로 표에 넣고 출처를 적는다.
3. 보고서 (짧게, 결론부터)
   - **잘된 것 3개**: 무엇이 / 숫자 / 왜 잘됐다고 보는지(구조·훅·시간·소재)
   - **아쉬운 것 3개**: 같은 형식. 원인은 가설로 쓴다.
   - **다음 할 일 3개**: 실행 단위(무엇을 언제 어떤 플랫폼에). 상위 소재는 `hub.py review --remix` 로 소재함에 되돌린다.
4. 플랫폼끼리 숫자를 직접 비교하지 않는다(플랫폼 안 백분위로). 표본이 5개 미만이면 "가설" 표시.
5. 공구 매출·마진 같은 내부 숫자는 보고서 파일에 쓰지 않는다(저장소가 공개).
